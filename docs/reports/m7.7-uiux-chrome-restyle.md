## Decision summary (also in DESIGN.md §0/§11.8)
- **Panels/badges/mute button — EVOLVED to rounded + soft:** rounded corners
  (`--radius-panel: 20px` modals, `--radius-control: 12px` chips/buttons/mute)
  + soft blurred shadows (`--shadow-panel`, `--shadow-control`), replacing
  hard-offset shadows/pixel-notch corners. Justification: the world art is now
  warm, soft-edged, gently-shaded illustration; a zero-radius hard-offset-
  shadow HUD on top of it reads as an unfinished placeholder skin, not one
  designed product, and the client's own SCOPE-03 ask ("less pixelated...
  so the user can see the object clearly") was fundamentally a softness/
  legibility preference that applies to chrome as much as world.
- **In-game text — EVOLVED:** dropped the hand-drawn 5×7 bitmap font
  (`FONT`/`drawText()`) for a natively-rendered bold rounded system font
  (`ui-rounded` → falls back to normal bold system sans) with a soft
  rounded-join stroke outline (`strokeText` then `fillText`). Same call
  signature, so ~30+ call sites don't change, only the function body.
- **Particles — MOSTLY KEPT, 2 of 4 effects softened:** `dust()` and
  `splash()` droplets go from square (`fillRect`) to filled circles
  (`ctx.arc`) — cheap, low-risk. `feathers()` and corn `sparkle()` (spark/
  star shape) stay hard-edged on purpose — their shape carries meaning
  (feather blade, star twinkle) per DESIGN §8's "shape, not just color" rule.
  Expanding splash ring unchanged (already soft/round).
- **Mute button:** resolved by making rounded corners the universal rule.
  Note: inspecting the actual `index.html` source, the mute button (and
  every other HUD element) is drawn with sharp `fillRect`/`strokeRect` —
  no rounded-corner code exists anywhere in the file today. The "already
  rounded" look in M7.5 screenshots is most likely a scaling/screenshot
  rendering artifact, not real code. Frontend implements a real, intentional,
  on-token `--radius-control: 12px` on the mute button matching every other
  control.
- **ISS-06 resolved (doc-only):** `imageSmoothingEnabled` stays `true`,
  scoped locally around world-art `drawImage` calls only, `false` as the
  canvas-wide default otherwise — exactly what frontend already implemented
  at M7.4. DESIGN §1.1 now states this as final rather than "M7.7's call, not
  decided yet," and clarifies the flag only affects raster `drawImage`
  scaling, not vector path/text rendering (so it was never actually blocking
  the new soft chrome).
- **No new assets:** this is a canvas-drawing/font/shadow/radius restyle only.
  `docs/ASSET_MANIFEST.md` and the accepted image registry (DESIGN §10.6.11)
  are untouched.
